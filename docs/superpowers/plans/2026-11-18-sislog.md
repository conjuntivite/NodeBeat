# SISLOG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** As MKs mandam seus eventos (syslog UDP) pelo IPsec. O NodeBeat guarda cada evento classificado no Mongo e mostra no cartão Eventos do detalhe da MK.

**Architecture:**
- **Receptor:** um serviço `syslog` novo no compose (mesma imagem do backend, `python -m nodebeat.syslog`), feito com `asyncio` da stdlib. Identifica a MK pelo IP de origem (`ip_tunel`) e grava em lote na coleção `eventos`, com TTL.
- **Classificação:** funções puras em `eventos.py`.
- **API:** expõe `GET /api/mks/{id}/eventos`.
- **Flutter:** ganha o cartão Eventos e o script "Ligar eventos" por MK.

**Tech Stack:**
- Backend: Python 3.14, FastAPI, motor, pytest + mongomock-motor + fakeredis (`backend/.venv`).
- Frontend: Flutter web (`C:/src/flutter`).
- MikroTik: RouterOS v6 ≥ 6.43 e v7.

**Spec:** `docs/superpowers/specs/2026-11-18-sislog-design.md`

## Global Constraints

- **Dependências:** nenhuma nova, nem no `pyproject.toml` nem no `pubspec.yaml`.
- **Porta do receptor:** UDP **5514** no container (usuário `nodebeat`, sem root). O compose publica `${NODEBEAT_SYSLOG_BIND_IP:?}:514:5514/udp`.
- **Datagrama:** cortado em **2048 bytes** e decodificado com `errors="replace"`.
- **Fila em memória:** teto de **10 000**. O lote grava a cada **1 s** ou **500** eventos.
- **Limite por MK:** **50 eventos/s**.
- **Mapa IP → MK:** recarrega a cada **60 s**, e também ao chegar IP desconhecido, no máximo 1×/10 s.
- **Log de descartes:** no máximo 1 linha/min.
- **Saúde:** `syslog:vivo` no Redis com TTL 90 s, renovado a cada 30 s.
- **Retenção:** `NODEBEAT_SYSLOG_DIAS`, padrão **30**, via índice TTL em `recebido_em`.
- **Data e hora:** a data é `recebido_em` (UTC). A linha da MK não traz hora (formato padrão, spike).
- **Tipos:** `login`, `login_falha`, `logout`, `config`, `interface`, `ipsec`, `dhcp`, `pppoe`, `reboot`, `erro`, `outro`.
- **API de eventos:** `limite` de 1 a 1000, padrão 200, ordem mais recente primeiro. `ate` é exclusivo (paginação). `syslog_ativo` = evento nas últimas 24 h.
- **Topics da MK:** `account,!debug`, `system,!debug`, `interface,!debug`, `ipsec,!debug`, `dhcp,!debug`, `pppoe,!debug`, `critical`, `error`. Sem `firewall`.
- **Formato na MK:** v6 `bsd-syslog=no`; v7 `remote-log-format=default` (sem `bsd-syslog`, que não existe na v7). A linha chega como `topicos mensagem`.
- **Ruído descartado no receptor:** tópico `debug`; login/logout do usuário `monitor` vindo de `NODEBEAT_IP_ORIGEM`.
- **IP fixo do container `syslog`:** `172.30.0.50`; depois de subir/recriar, `conntrack -D -p udp --dport 514` no CT.
- **Script RouterOS:** 100% ASCII. A action se chama `nodebeat` e a limpeza é por `name="nodebeat"` / `action="nodebeat"`.
- **Repositório público:** IPs reais, nomes de clientes e usuários reais de MK **nunca** vão ao repo, nem nas amostras de teste (use placeholders e IPs de documentação `192.0.2.x`, `198.51.100.x`, `203.0.113.x`). Valores reais ficam só em `docs/*.local.md` e no `.env` do CT.
- **Trade UI:** só tokens, temas claro e escuro, `tabular-nums` na hora do evento, sem emoji como ícone.
- **Deploy:** só com aprovação do usuário. Nenhum push sem aprovação, e antes de qualquer push rodar o grep de dados reais no diff.

## Review Focus

1. **Datagrama com lixo** (binário, só vírgulas, linha antiga com cabeçalho BSD, vazio): o receptor não pode cair. Vira `outro` ou é descartado. → Task 1 `test_lixo_nao_quebra`, Task 3 `test_datagrama_vazio_ignorado`.
2. **Mongo fora do ar durante a gravação:** o gravador loga, mantém o processo vivo e segue descartando pela fila cheia. → Task 3 `test_gravador_sobrevive_erro_do_mongo`.
3. **MK com `ip_tunel` alterado pelo painel:** depois da recarga do mapa, os eventos vão para a MK certa, e o IP antigo vira desconhecido. → Task 3 `test_mapa_reflete_alteracao`.
4. **Busca `q` com caracteres de regex** (`.*`, `(`): é escapada e não dá 500. → Task 4 `test_q_com_regex_escapado`.
5. **Script "Ligar eventos" para MK sem `ip_origem` configurado** (`NODEBEAT_IP_ORIGEM` vazio): o painel não gera script quebrado e mostra aviso. → Task 7 `test_ligar_eventos_sem_ip_origem`.

### Task 3: Receptor UDP (`syslog.py`) e deploy

**Files:**
- Create: `backend/nodebeat/syslog.py`
- Modify: `deploy/compose.yml`, `deploy/.env.example`, `deploy/README.md`
- Test: `backend/tests/test_syslog.py`

**Interfaces:**
- Consumes: `eventos.evento` (Task 1); `store.garantir_indices_eventos`, `store.inserir_eventos`, `store.list_mks` (Task 2); `config.load_settings`.
- Produces:
  - `async mapa_ips(db) -> dict[str, str | None]`: `ip_tunel → mk_id`, e `None` quando o IP é de mais de uma MK.
  - `class Receptor(asyncio.DatagramProtocol)`:
    - construtor `__init__(self, mapa: dict[str, str | None], fila: asyncio.Queue, pedir_recarga: Callable[[], None], ip_origem: str | None = None, limite_por_s: int = 50, relogio: Callable[[], float] = time.monotonic)`;
    - atributo `mapa` (trocável);
    - `descartes: collections.Counter`, com chaves `("desconhecido", ip)`, `("ambiguo", ip)`, `("limite", mk_id)` e `("fila_cheia", "")`.

    O `datagram_received` ignora dado vazio, chama `pedir_recarga()` em IP desconhecido e monta `evento(...)`, descarta em silêncio (sem contar) se `eventos.ruido(ev, ip_origem)`, aplica o limite por MK e faz `fila.put_nowait(ev)`. `QueueFull` conta como descarte. O `main` passa `settings.ip_origem`.
  - `async gravar(db, fila: asyncio.Queue, intervalo_s: float = 1.0, lote: int = 500) -> None`: laço infinito que junta até `lote` itens ou até passar `intervalo_s` e chama `inserir_eventos`. Exceção é logada (`log.warning`, só o tipo) e o lote é perdido. `ponytail:` lote perdido se o Mongo cair; o UDP já é com perda.
  - `async main() -> None` e `if __name__ == "__main__": asyncio.run(main())`. O `main` faz, nesta ordem:
    1. carrega settings, Mongo e Redis, como `worker.main`;
    2. `garantir_indices_eventos`;
    3. `mapa_ips`;
    4. abre o endpoint `0.0.0.0:5514` com `Queue(maxsize=10_000)`;
    5. inicia as tarefas `gravar`, recarga (60 s, ou na hora quando pedida, com intervalo mínimo de 10 s), `syslog:vivo` (`ex=90`, a cada 30 s) e log de descartes (1×/min, só se houver, depois zera).
