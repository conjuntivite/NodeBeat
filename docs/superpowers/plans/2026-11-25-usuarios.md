# Painel de usuários com tema salvo — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** níveis admin/comum, tela de Usuários (só admin), "Minha conta" para trocar a própria senha e tema salvo por usuário.

**Architecture:** a coleção `users` ganha `admin` e `tema`. O login atual (argon2, `sess:<token>` em Redis) passa a indexar os tokens por usuário em `sess_u:<usuario>`. `auth.current_user` lê o usuário no Mongo, e a nova dependência `auth.admin_user` responde 403. No front, um `ValueNotifier<Eu?>` global guarda quem está logado: a barra lateral mostra "Usuários" para admin, e o botão de tema grava a escolha na API.

**Tech Stack:** FastAPI, motor/Mongo, redis.asyncio e argon2 no backend; Flutter web com material_ui e `http` no front.

**Spec:** `docs/superpowers/specs/2026-11-25-usuarios-design.md`

## Global Constraints

- **Testes:**
  - backend com `.venv/Scripts/python -m pytest -q`, a partir de `backend/`;
  - frontend com `/c/src/flutter/bin/flutter test`, e `/c/src/flutter/bin/flutter analyze` limpo, a partir de `frontend/`.
- TDD: o teste vem antes do código.
- **Segredos:** nenhuma senha ou hash em log, erro ou resposta, e `GET /api/usuarios` nunca devolve `senha_hash`.
- **Senha:** mínimo de 12 caracteres (`cli.MIN_SENHA`), validado na API e na tela.
- **Nome de usuário:** normalizado com `strip().lower()` em toda entrada.
- **Migração sem script:** um documento sem o campo `admin` conta como admin (`u.get("admin", True)`), porque hoje todos os usuários vieram da CLI. Usuário novo, pela tela ou pela CLI sem `--admin`, grava `admin: False`.
- **Travas (409):**
  - ninguém se remove nem se rebaixa;
  - o último admin não pode ser removido nem rebaixado.
- **Visual:**
  - padrão Inviolável/pink do projeto: `tokensOf(context)`, `Selo`, `TradeCard`, `AppShell`;
  - nada de cor ou tamanho fixo no código;
  - os dois temas;
  - a linha de batimentos (`widgets/heartbeat.dart`) fica intocada.
- **Tema:** quem nunca escolheu entra no claro (`ThemeMode.light`, que já está no `theme.dart` da árvore de trabalho).
- Commits com o trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Usuário removido com aba aberta: a próxima chamada dá 401, mesmo que o token ainda exista no Redis. `current_user` consulta o Mongo (teste na Task 1).
- Admin redefine a senha de outro: todas as sessões do outro caem. Na troca da própria senha, só a sessão atual sobrevive (testes na Task 2).
- Nome com maiúsculas ou espaços em `POST /api/usuarios` e nas rotas `{u}`: é tratado como o mesmo usuário (teste na Task 2).
- Recarregar a página já logado aplica o tema salvo, e não só logo depois do login (teste na Task 3).
- Usuário comum não vê o item "Usuários", e a API responde 403 mesmo assim (testes nas Tasks 2 e 4).

### Task 1: Backend — dados, sessões por usuário e dependências

**Files:**

- Test: `backend/tests/test_auth.py`

**Interfaces:**
- Produces:
  - **`store`:**
    - `insert_user(db, usuario, senha_hash, admin: bool = False) -> str`;
    - `listar_users(db) -> list[dict]`: devolve `usuario`, `admin` (bool, com o padrão True) e `criado_em`, sem hash, ordenado por usuário;
    - `atualizar_user(db, usuario, campos: dict) -> bool`: True se o usuário existe;
    - `apagar_user(db, usuario) -> bool`;
    - `contar_admins(db) -> int`: conta `admin != False`.

    - `login`: além de `sess:<token>`, faz `SADD sess_u:<usuario> <token>` com `EXPIRE SESSAO_TTL`;
    - `encerrar_sessoes(r, usuario, manter: str | None = None) -> None`: apaga cada `sess:<t>` do conjunto, menos `manter`, e acerta o conjunto;
    - `current_user(request) -> {"usuario", "admin": bool, "tema": str | None, "token": str}`: responde 401 se o usuário não existe mais no Mongo;
    - `admin_user` (dependência): igual a `current_user`, mas responde 403 com "Acesso restrito ao admin" quando não é admin.
  - `GET /api/auth/me` devolve `{usuario, admin, tema}`, sem o token.
  - CLI: `create-user <usuario> [--admin]`.

### Task 2: Backend — rotas de conta e de usuários

**Files:**
- Modify: `backend/nodebeat/api.py`
- Test: `backend/tests/test_api_usuarios.py` (novo, com os fixtures copiados de `test_auth.py`)

**Interfaces:**
- Consumes: tudo o que a Task 1 produz.
- Produces:
  - **Qualquer usuário logado:**
    - `PUT /api/auth/tema {tema: "claro"|"escuro"}` → 204. Outro valor dá 422;
    - `PUT /api/auth/senha {atual, nova}` → 204. Senha atual errada dá 400 com "Senha atual incorreta". Nova com menos de 12 caracteres dá 422 com msg "Mínimo de 12 caracteres". Depois chama `encerrar_sessoes(r, u, manter=token)`.
  - **Só admin (`admin_user`):**
    - `GET /api/usuarios` → `[{usuario, admin, criado_em}]`;
    - `POST /api/usuarios {usuario, senha, admin=False}` → 201 com `{usuario}`. Repetido dá 409 com "Usuário já existe";
    - `PUT /api/usuarios/{u} {senha?, admin?}` → 204, ou 404. Com `senha`, encerra todas as sessões de `u`;
    - `DELETE /api/usuarios/{u}` → 204, ou 404. Encerra as sessões de `u`.
  - **Travas:**
    - `u == eu` em DELETE, ou `admin: false` aplicado a si mesmo, dá 409 com "Você não pode remover nem rebaixar a si mesmo";
    - rebaixar ou remover o último admin dá 409 com "Precisa haver ao menos um admin".
  - Acrescente `"nova": "Mínimo de 12 caracteres"` ao `_MSG_422`.
